01

Dasar Java dan lingkungan pengembangan

Java adalah bahasa pemrograman berorientasi objek yang source code-nya dikompilasi menjadi bytecode, lalu dijalankan oleh JVM. Alur ini memisahkan penulisan program dari eksekusinya dan membantu bytecode berjalan di berbagai sistem operasi yang memiliki JVM.

JDK dipakai untuk mengembangkan program; di dalamnya tersedia compiler javac dan perangkat runtime. IDE seperti IntelliJ IDEA menyatukan editor, compiler, runner, dan debugger agar proses menulis serta mencari kesalahan lebih mudah.

JDK

JDK adalah paket untuk mengembangkan program Java, termasuk compiler javac.

JRE

JRE menyediakan runtime dan library yang dibutuhkan untuk menjalankan program Java.

JVM

JVM adalah mesin virtual yang mengeksekusi bytecode Java. JRE menyediakan lingkungan untuk menjalankan JVM, sedangkan JDK menambahkan alat pengembangan.

Source code, compiler, dan bytecode

Source code adalah instruksi Java yang ditulis programmer. Compiler mengubahnya menjadi bytecode dalam file .class, lalu JVM mengeksekusinya. Bytecode memungkinkan program berjalan di sistem berbeda selama sistem tersebut memiliki JVM yang sesuai.

IDE dan nama file

IDE seperti IntelliJ IDEA menyatukan editor, compiler, runner, dan debugger. Nama file harus sama dengan nama class yang dideklarasikan public, termasuk huruf besar-kecil.

Source code, compiler, dan bytecode

Source code adalah instruksi Java yang ditulis programmer. Compiler mengubahnya menjadi bytecode di file .class; JVM lalu mengeksekusi bytecode tersebut. Karena format bytecode sama, program dapat dijalankan pada sistem berbeda selama tersedia JVM yang sesuai.

Class, method, dan main

Class menjadi wadah deklarasi kode. Method adalah bagian bernama yang berisi instruksi untuk melakukan pekerjaan tertentu. Method main dengan bentuk public static void main(String[] args) menjadi titik masuk program yang dijalankan Java.

IDE dan nama file

IDE seperti IntelliJ IDEA menggabungkan editor, compiler, runner, dan debugger. Jika sebuah class dideklarasikan public, nama file Java harus sama dengan nama class tersebut, termasuk huruf besar-kecil.

Struktur program dan alur eksekusi

public class HaloJava {
    public static void main(String[] args) {
        System.out.println("Siap belajar PBO");
    }
}

Cara memanggil

Simpan program sebagai HaloJava.java, lalu kompilasi dan jalankan dari terminal:

javac HaloJava.java
java HaloJava

Output

Siap belajar PBO

main adalah titik awal program. Perintah pertama mengompilasi source; perintah kedua menjalankan class melalui JVM.

02

Class dan object

Class

Class adalah cetak biru yang mendefinisikan data dan perilaku yang dapat dimiliki object. Deklarasi class sendiri belum membuat object.

Atribut dan method

Atribut menyimpan keadaan/data object, sedangkan method berisi perilaku atau operasi yang dapat dilakukan object. Pada contoh ini, nama dan ipk adalah atribut; tampilkanData() adalah method.

Object dan instansiasi

Object adalah satu instance nyata dari class. Operator new membuat object dan mengembalikan referensi yang dapat disimpan dalam variabel. Setiap object Mahasiswa memiliki nilai atributnya sendiri.

Contoh kode dan pemanggilan

Atribut menyimpan keadaan object; method melakukan tindakan. Buat object dengan new, isi atribut, lalu panggil method melalui referensinya.

class Mahasiswa {
    String nama;
    double ipk;

    void tampilkanData() {
        System.out.println(nama + " — IPK " + ipk);
    }
}

public class MainMahasiswa {
    public static void main(String[] args) {
        Mahasiswa mhs = new Mahasiswa();
        mhs.nama = "Alya";
        mhs.ipk = 3.75;
        mhs.tampilkanData();
    }
}

Output

Alya — IPK 3.75

mhs adalah referensi ke object Mahasiswa. Setiap object punya nilai atribut instance sendiri, sementara method mendefinisikan perilaku yang dapat dipanggil.

Class menjawab “data dan perilaku apa yang dimiliki?”, sedangkan object adalah satu wujud nyata dengan nilai datanya sendiri.
03

Constructor, this, dan static

Constructor

Constructor adalah blok khusus yang dijalankan saat object dibuat dengan new. Namanya sama dengan class dan tidak memiliki tipe pengembalian; biasanya constructor mengisi nilai awal agar object siap dipakai.

Constructor overloading

Constructor overloading berarti satu class memiliki beberapa constructor dengan jumlah atau tipe parameter berbeda. Java memilih constructor yang cocok dengan argumen pada new; nama parameter saja tidak membentuk signature yang berbeda.

Keyword this

this merujuk object yang metodenya sedang dijalankan. Dalam this.nama = nama, sisi kiri adalah field object dan sisi kanan adalah parameter. Bentuk this(...) memanggil constructor lain di class yang sama dan harus menjadi instruksi pertama constructor.

Field instance

Field instance adalah data milik masing-masing object. Nilainya bisa berbeda antara satu object Produk dan object lainnya, seperti nama dan harga.

Field dan method static

Anggota static dimiliki class, bukan salinan terpisah pada tiap object. Karena jumlahProduk adalah satu counter bersama, nilainya diakses melalui Produk.jumlahProduk dan bertambah setiap constructor produk dijalankan.

Contoh kode dan pemanggilan

Simpan sebagai MainProduk.java. Program membuat satu object dengan constructor default dan satu dengan parameter.

class Produk {
    String nama;
    double harga;
    static int jumlahProduk;

    Produk() {
        this("Belum diberi nama", 0);
    }

    Produk(String nama, double harga) {
        this.nama = nama;
        this.harga = harga;
        jumlahProduk++;
    }
}

public class MainProduk {
    public static void main(String[] args) {
        Produk p1 = new Produk();
        Produk p2 = new Produk("Buku", 25000);
        System.out.println(p1.nama);
        System.out.println(p2.nama + " Rp" + p2.harga);
        System.out.println("Jumlah produk: " + Produk.jumlahProduk);
    }
}

Output

Belum diberi nama
Buku Rp25000.0
Jumlah produk: 2

Constructor tanpa parameter memanggil constructor kedua melalui this(...). Setiap pemanggilan constructor berparameter menaikkan counter yang sama.

Parameter constructor yang berbeda membentuk signature berbeda. Hanya perbedaan nama parameter tidak cukup untuk overloading.
04

Encapsulation dan access modifier

Encapsulation

Encapsulation membungkus state (atribut) dan perilaku (method) dalam class serta membatasi akses langsung ke detail internal. Tujuannya agar class menjaga sendiri aturan perubahan datanya.

Access modifier

private membatasi anggota ke class itu; protected mengizinkan package dan subclass mengaksesnya; public membuka anggota bagi pemanggil yang dapat melihat class.

Getter, setter, dan validasi

Getter menyediakan cara membaca atribut private; setter menyediakan cara mengubahnya. Validasi pada setter mencegah nilai yang melanggar aturan masuk ke object.

  • private: hanya dapat diakses dari class itu sendiri.
  • protected: dapat diakses di package yang sama dan oleh subclass.
  • public: dapat diakses dari mana saja yang melihat class tersebut.

Contoh kode dan pemanggilan

class Rekening {
    private double saldo;

    public double getSaldo() {
        return saldo;
    }

    public void setSaldo(double saldo) {
        if (saldo >= 0) {
            this.saldo = saldo;
        }
    }
}

public class MainRekening {
    public static void main(String[] args) {
        Rekening rekening = new Rekening();
        rekening.setSaldo(250000);
        rekening.setSaldo(-100);
        System.out.println(rekening.getSaldo());
    }
}

Output

250000.0

Di luar class, kode membaca saldo lewat getSaldo(), bukan mengubah saldo secara langsung. Validasi berada di pintu perubahan, yaitu setter. Inilah information hiding: class mengatur sendiri cara data internal dibaca dan diubah, sehingga pemanggil tidak bisa sembarang merusak keadaan object.

Getter/setter bukan sekadar boilerplate: gunakan setter untuk menjaga aturan, misalnya saldo tidak boleh negatif atau IPK harus berada di rentang 0–4.
05

Inheritance dan keyword super

Inheritance

Inheritance (pewarisan) memungkinkan class baru menerima atribut dan method dari class lain. Gunakan extends saat hubungan antarclass memang “adalah jenis dari” (IS-A), misalnya kucing adalah hewan.

Superclass dan subclass

Superclass adalah class yang mewariskan bagian-bagiannya. Subclass adalah class yang menerima warisan dan dapat menambahkan perilaku khusus. Pada contoh, Hewan superclass dan Kucing subclass.

Keyword super

super merujuk bagian superclass. Ekspresi super(nama) memanggil constructor induk yang menerima nama, sehingga data superclass diinisialisasi.

Constructor chaining

Constructor chaining adalah rangkaian pemanggilan constructor dalam hierarki pewarisan. Constructor superclass dijalankan sebelum inisialisasi subclass selesai; karena itu pemanggilan super(...) harus menjadi instruksi pertama constructor subclass.

class Hewan {
    protected String nama;

    Hewan(String nama) {
        this.nama = nama;
    }

    void makan() {
        System.out.println(nama + " sedang makan");
    }
}

class Kucing extends Hewan {
    Kucing(String nama) {
        super(nama);
    }

    void mengeong() {
        System.out.println(nama + ": Meong!");
    }
}

Kucing IS-A Hewan, jadi object kucing dapat memakai method warisan seperti makan() sekaligus memiliki perilaku khusus mengeong(). Constructor subclass memanggil super(nama) sebagai langkah pertama agar bagian superclass terinisialisasi sebelum bagian subclass.

Contoh pemanggilan dan output

Letakkan kode berikut di class MainHewan untuk membuat object dan memanggil method warisan maupun method subclass:

public class MainHewan {
    public static void main(String[] args) {
        Kucing kucing = new Kucing("Milo");
        kucing.makan();
        kucing.mengeong();
    }
}

Output:

Milo sedang makan
Milo: Meong!
Inheritance cocok untuk relasi “adalah jenis dari”. Kalau relasinya “memiliki”, biasanya gunakan composition dengan menyimpan object lain sebagai atribut.
06

Class diagram: inheritance dan composition

Pertemuan ini menggabungkan relasi class dengan studi kasus kendaraan dan tiket parkir. Class diagram menggambarkan struktur program sebelum atau selama implementasi.

Bagian-bagian class diagram

Kotak class biasanya menampilkan nama class, atribut, dan method. Atribut menggambarkan data yang disimpan, method menggambarkan operasi yang tersedia, sedangkan garis dan panah menunjukkan relasi antarclass.

Inheritance dan relasi IS-A

Relasi IS-A berarti satu class merupakan jenis dari class lain. Mobil dan Motor adalah Kendaraan, sehingga dapat memakai inheritance melalui extends. Pada diagram UML, garis inheritance berujung segitiga kosong di superclass.

Composition dan relasi HAS-A

Relasi HAS-A berarti sebuah object menyimpan atau memiliki object lain sebagai bagian datanya. TiketParkir memiliki atribut Kendaraan; tiket bukan jenis kendaraan, jadi relasinya composition, bukan inheritance.

Dependency

Dependency berarti satu class menggunakan class lain, misalnya Main membuat dan memanggil object kendaraan. Hubungan penggunaan ini tidak berarti salah satu class menjadi bagian atau turunan class lainnya.

Constructor overloading dan static

Constructor overloading memberi pilihan membuat tiket dengan tarif default atau tarif khusus. Field static jumlahTiket menyimpan satu hitungan bersama untuk semua object tiket.

class Kendaraan {
    private String nomorPolisi;
    private String merk;

    Kendaraan(String nomorPolisi, String merk) {
        this.nomorPolisi = nomorPolisi;
        this.merk = merk;
    }

    public String getNomorPolisi() { return nomorPolisi; }
    public String getMerk() { return merk; }
}

class Mobil extends Kendaraan {
    private int jumlahPintu;

    Mobil(String nomorPolisi, String merk, int jumlahPintu) {
        super(nomorPolisi, merk);
        this.jumlahPintu = jumlahPintu;
    }
}

class Motor extends Kendaraan {
    private String jenisMotor;

    Motor(String nomorPolisi, String merk, String jenisMotor) {
        super(nomorPolisi, merk);
        this.jenisMotor = jenisMotor;
    }
}
class TiketParkir {
    private static int jumlahTiket = 0;
    private Kendaraan kendaraan; // HAS-A
    private double tarifPerJam;

    TiketParkir(Kendaraan kendaraan) {
        this(kendaraan, 5000);
    }

    TiketParkir(Kendaraan kendaraan, double tarifPerJam) {
        this.kendaraan = kendaraan;
        this.tarifPerJam = tarifPerJam;
        jumlahTiket++;
    }

    static int getJumlahTiket() {
        return jumlahTiket;
    }
}

Contoh pemanggilan dan output

Simpan class pendukung sebagai file lain dalam package yang sama. Berikut cara membuat object Mobil, lalu dua tiket dengan constructor berbeda:

public class MainParkir {
    public static void main(String[] args) {
        Kendaraan mobil = new Mobil("B 1234 ABC", "Toyota", 4);
        new TiketParkir(mobil);
        new TiketParkir(mobil, 7000);
        System.out.println(mobil.getMerk());
        System.out.println("Total tiket: " + TiketParkir.getJumlahTiket());
    }
}

Output

Toyota
Total tiket: 2
Ingat untuk diagram: panah inheritance mengarah dari subclass ke superclass; atribut object pada TiketParkir menggambarkan HAS-A. Hubungan penggunaan oleh Main adalah dependency, bukan IS-A.

Class diagram membantu merancang struktur sebelum kode ditulis: kotak class merangkum atribut dan method, sementara garis dan panah menyatakan hubungan. Composition menaruh object bagian sebagai atribut class pemilik; tiket parkir mencatat kendaraan yang sedang diparkir, tetapi bukan jenis kendaraan.

07

Polymorphism, casting, dan dispatch

Polymorphism

Polymorphism berarti “banyak bentuk”: referensi bertipe umum dapat menunjuk object dari subclass berbeda. Pemanggil dapat memakai method yang sama, sementara hasil perilakunya mengikuti jenis object sebenarnya.

Overloading

Overloading menyediakan beberapa method bernama sama dengan daftar parameter berbeda. Compiler memilih versi yang cocok berdasarkan jumlah dan tipe argumen; tipe kembalian saja tidak cukup membedakan method.

Overriding

Overriding terjadi ketika subclass menyediakan implementasi baru untuk method superclass dengan signature yang sama. Method tersebut harus sesuai aturan pewarisan; anotasi @Override meminta compiler memeriksa bahwa method benar-benar melakukan override.

Upcasting

Upcasting menyimpan object subclass dalam variabel bertipe superclass, seperti Bentuk bentuk = new Lingkaran(3). Ini otomatis dan memungkinkan beberapa jenis object diperlakukan melalui tipe umum.

Downcasting dan instanceof

Downcasting mengubah referensi superclass menjadi referensi subclass agar fitur khusus subclass dapat diakses. Cast harus eksplisit dan hanya berhasil bila object aktual memang tipe tersebut; periksa dengan instanceof sebelum melakukan cast.

Dynamic dispatch

Dynamic dispatch adalah pemilihan implementasi method override saat runtime berdasarkan object aktual, bukan tipe referensinya. Karena bentuk menunjuk Lingkaran, pemanggilan bentuk.luas() menjalankan method milik Lingkaran.

class Bentuk {
    double luas() { return 0; }
}

class Lingkaran extends Bentuk {
    private double jariJari;

    Lingkaran(double jariJari) {
        this.jariJari = jariJari;
    }

    @Override
    double luas() {
        return Math.PI * jariJari * jariJari;
    }
}

Bentuk bentuk = new Lingkaran(3); // upcasting otomatis
System.out.println(bentuk.luas()); // method Lingkaran dipanggil
  • Upcasting: referensi subclass ke tipe superclass; otomatis dan aman.
  • Downcasting: referensi superclass ke subclass; eksplisit dan hanya aman bila object memang tipe tersebut. Periksa dengan instanceof.
  • Dynamic method dispatch: pemilihan method override berdasarkan tipe object aktual, bukan tipe referensi.

Contoh pemanggilan dan output

Simpan class Bentuk dan Lingkaran di atas bersama class berikut. Referensi induk memanggil method yang dioverride pada object lingkaran:

public class MainBentuk {
    public static void main(String[] args) {
        Bentuk bentuk = new Lingkaran(3);
        System.out.printf("Luas: %.2f%n", bentuk.luas());

        if (bentuk instanceof Lingkaran) {
            Lingkaran lingkaran = (Lingkaran) bentuk;
            System.out.println(lingkaran.getClass().getSimpleName());
        }
    }
}

Output

Luas: 28.27
Lingkaran

Overloading dan overriding berbeda: overloading mengubah daftar parameter, sedangkan overriding mempertahankan signature method superclass dan mengganti perilakunya.

Manfaatnya: kode pemanggil dapat bekerja dengan tipe induk yang sama, sementara tiap object memberi perilaku yang sesuai dengan jenis konkretnya.

Studi kasus dari praktikum

Contoh berikut merangkai beberapa konsep PBO dalam alur yang lebih nyata. Tiap kasus menyorot masalah, desain object, dan konsep yang muncul.

1. Transaksi e-commerce: saldo dan stok

Di contoh MainPengguna.java, object pengguna membeli object produk. Method transaksi menghitung total, membandingkan dengan saldo, lalu hanya mengubah saldo dan stok jika saldo cukup. Kondisi gagal tidak boleh mengurangi stok.

class Produk {
    String nama;
    double harga;
    int stok;

    Produk(String nama, double harga, int stok) {
        this.nama = nama;
        this.harga = harga;
        this.stok = stok;
    }
}

class Pengguna {
    String nama;
    double saldo;

    Pengguna(String nama, double saldo) {
        this.nama = nama;
        this.saldo = saldo;
    }

    void beli(Produk produk, int jumlah) {
        double total = produk.harga * jumlah;
        if (jumlah > 0 && jumlah <= produk.stok && saldo >= total) {
            saldo -= total;
            produk.stok -= jumlah;
            System.out.println("Transaksi berhasil");
        } else {
            System.out.println("Transaksi gagal");
        }
    }
}

public class MainToko {
    public static void main(String[] args) {
        Pengguna user = new Pengguna("Abia", 500000);
        Produk keyboard = new Produk("Keyboard", 120000, 5);
        user.beli(keyboard, 2);
        user.beli(keyboard, 3);
        System.out.println("Saldo akhir: " + user.saldo);
        System.out.println("Stok akhir: " + keyboard.stok);
    }
}

Output

Transaksi berhasil
Transaksi gagal
Saldo akhir: 260000.0
Stok akhir: 3

Konsep: object saling berinteraksi lewat method dan parameter. Perhatikan validasi stok, jumlah, dan saldo sebelum mengubah state object.

2. Tiket parkir: relasi kendaraan

Kasus laporan pertemuan 6 memodelkan kendaraan umum, variasi mobil/motor, dan tiket yang merekam kendaraan. Mobil dan motor adalah kendaraan (IS-A); tiket memiliki kendaraan (HAS-A). Counter static mencatat jumlah tiket lintas object.

class Kendaraan {
    private String nomorPolisi;
    private String merk;

    Kendaraan(String nomorPolisi, String merk) {
        this.nomorPolisi = nomorPolisi;
        this.merk = merk;
    }

    String getNomorPolisi() { return nomorPolisi; }
    String getMerk() { return merk; }
}

class Mobil extends Kendaraan {
    private int jumlahPintu;

    Mobil(String nomorPolisi, String merk, int jumlahPintu) {
        super(nomorPolisi, merk);
        this.jumlahPintu = jumlahPintu;
    }
}

class TiketParkir {
    private static int jumlahTiket;
    private Kendaraan kendaraan;
    private double tarifPerJam;

    TiketParkir(Kendaraan kendaraan) {
        this(kendaraan, 5000);
    }

    TiketParkir(Kendaraan kendaraan, double tarifPerJam) {
        this.kendaraan = kendaraan;
        this.tarifPerJam = tarifPerJam;
        jumlahTiket++;
    }

    static int getJumlahTiket() {
        return jumlahTiket;
    }
}

Contoh pemanggilan

public class MainParkir {
    public static void main(String[] args) {
        Kendaraan mobil = new Mobil("B 1234 ABC", "Toyota", 4);
        TiketParkir reguler = new TiketParkir(mobil);
        TiketParkir khusus = new TiketParkir(mobil, 7000);
        System.out.println(mobil.getMerk());
        System.out.println("Total tiket: " + TiketParkir.getJumlahTiket());
    }
}

Output

Toyota
Total tiket: 2

Konsep: super(...) mengisi data bagian superclass; overloaded constructor menyediakan tarif default atau tarif khusus; composition memisahkan tanggung jawab tiket dari detail kendaraan.

3. Penggajian: polymorphism pegawai

Contoh TugasMandiriPegawai.java menyimpan berbagai jenis pegawai dalam array bertipe induk. Saat hitungGaji() dipanggil, Java menjalankan implementasi sesuai object sebenarnya. Pegawai tetap menambahkan bonus; method bonus juga di-overload agar bisa memakai persentase eksplisit.

class Pegawai {
    String nama;
    double gajiPokok;

    Pegawai(String nama, double gajiPokok) {
        this.nama = nama;
        this.gajiPokok = gajiPokok;
    }

    double hitungBonus() { return 0; }
    double hitungBonus(double persen) { return gajiPokok * persen; }
    double hitungGaji() { return gajiPokok + hitungBonus(); }
}

class PegawaiTetap extends Pegawai {
    double persenBonus;

    PegawaiTetap(String nama, double gajiPokok, double persenBonus) {
        super(nama, gajiPokok);
        this.persenBonus = persenBonus;
    }

    @Override
    double hitungGaji() {
        return gajiPokok + hitungBonus(persenBonus);
    }
}

Pegawai[] pegawai = {
    new Pegawai("Andi", 5_000_000),
    new PegawaiTetap("Budi", 6_000_000, 0.10)
};

for (Pegawai p : pegawai) {
    System.out.println(p.nama + ": " + p.hitungGaji());
}

Contoh pemanggilan

Letakkan kode demo ini di main pada class MainPayroll:

public class MainPayroll {
    public static void main(String[] args) {
        Pegawai[] pegawai = {
            new Pegawai("Andi", 5000000),
            new PegawaiTetap("Budi", 6000000, 0.10),
            new PegawaiTetap("Citra", 7000000, 0.15)
        };

        for (Pegawai p : pegawai) {
            System.out.printf("%s: Rp%.0f%n", p.nama, p.hitungGaji());
        }
        System.out.printf("Bonus Andi (5%%): Rp%.0f%n",
            pegawai[0].hitungBonus(0.05));
    }
}

Output

Andi: Rp5000000
Budi: Rp6600000
Citra: Rp8050000
Bonus Andi (5%): Rp250000

Konsep: upcasting terjadi saat PegawaiTetap dimasukkan ke array Pegawai[]. Dynamic dispatch memilih hitungGaji() yang override saat runtime; overloading membedakan hitungBonus() dan hitungBonus(double) dari parameternya.
