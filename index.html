01

Dasar Java dan lingkungan pengembangan

Java adalah bahasa pemrograman berorientasi objek yang source code-nya dikompilasi menjadi bytecode, lalu dijalankan oleh JVM. Alur ini memisahkan penulisan program dari eksekusinya dan membantu bytecode berjalan di berbagai sistem operasi yang memiliki JVM.

JDK dipakai untuk mengembangkan program; di dalamnya tersedia compiler javac dan perangkat runtime. IDE seperti IntelliJ IDEA menyatukan editor, compiler, runner, dan debugger agar proses menulis serta mencari kesalahan lebih mudah.

  • JDK: perangkat untuk mengembangkan aplikasi Java.
  • JRE: lingkungan dan library untuk menjalankan program.
  • JVM: mengeksekusi bytecode Java.
  • Nama file harus sama persis dengan nama public class.

Struktur program dan alur eksekusi

public class HaloJava {
    public static void main(String[] args) {
        System.out.println("Siap belajar PBO");
    }
}
javac HaloJava.java
java HaloJava

main adalah titik awal program. Perintah pertama mengompilasi source; perintah kedua menjalankan class melalui JVM.

02

Class dan object

Class adalah cetak biru yang mendefinisikan atribut (data) dan method (perilaku). Object adalah instance yang dibuat dari class. Class belum menjadi object sampai diinstansiasi dengan new.

class Mahasiswa {
    String nama;
    double ipk;

    void tampilkanData() {
        System.out.println(nama + " — IPK " + ipk);
    }
}

class Main {
    public static void main(String[] args) {
        Mahasiswa mhs = new Mahasiswa();
        mhs.nama = "Alya";
        mhs.ipk = 3.75;
        mhs.tampilkanData();
    }
}

mhs adalah referensi ke object Mahasiswa. Setiap object punya nilai atribut instance sendiri, sementara method mendefinisikan perilaku yang dapat dipanggil.

Class menjawab “data dan perilaku apa yang dimiliki?”, sedangkan object adalah satu wujud nyata dengan nilai datanya sendiri.
03

Constructor, this, dan static

Constructor berjalan saat object dibuat dan menginisialisasi datanya. Constructor overloading berarti satu class punya beberapa constructor dengan daftar parameter berbeda. this merujuk object aktif, lazim untuk membedakan atribut dan parameter.

class Produk {
    String nama;
    double harga;
    static int jumlahProduk;

    Produk() {
        this("Belum diberi nama", 0);
    }

    Produk(String nama, double harga) {
        this.nama = nama;
        this.harga = harga;
        jumlahProduk++;
    }
}

Produk p = new Produk("Buku", 25000);
System.out.println(Produk.jumlahProduk);

Instance member dimiliki masing-masing object. Static member dimiliki bersama oleh class, sehingga contoh penghitung jumlah object diakses melalui Produk.jumlahProduk. Constructor dipanggil ketika new membuat object; overloading memberi beberapa cara inisialisasi, sedangkan this(...) meneruskan inisialisasi ke constructor lain dalam class yang sama.

Parameter constructor yang berbeda membentuk signature berbeda. Hanya perbedaan nama parameter tidak cukup untuk overloading.
04

Encapsulation dan access modifier

Encapsulation membungkus data dan perilaku di dalam class serta mengontrol akses ke detail internalnya. Atribut biasanya dibuat private; getter membaca nilai dan setter mengubahnya. Setter bisa memvalidasi data supaya object tetap dalam keadaan valid.

  • private: hanya dapat diakses dari class itu sendiri.
  • protected: dapat diakses di package yang sama dan oleh subclass.
  • public: dapat diakses dari mana saja yang melihat class tersebut.
class Rekening {
    private double saldo;

    public double getSaldo() {
        return saldo;
    }

    public void setSaldo(double saldo) {
        if (saldo >= 0) {
            this.saldo = saldo;
        }
    }
}

Di luar class, kode membaca saldo lewat getSaldo(), bukan mengubah saldo secara langsung. Validasi berada di pintu perubahan, yaitu setter. Inilah information hiding: class mengatur sendiri cara data internal dibaca dan diubah, sehingga pemanggil tidak bisa sembarang merusak keadaan object.

Getter/setter bukan sekadar boilerplate: gunakan setter untuk menjaga aturan, misalnya saldo tidak boleh negatif atau IPK harus berada di rentang 0–4.
05

Inheritance dan keyword super

Inheritance memungkinkan subclass mewarisi perilaku dan atribut yang dapat diakses dari superclass. Gunakan extends untuk relasi “adalah jenis dari” (IS-A). super memanggil constructor atau anggota superclass; constructor superclass berjalan lebih dahulu.

class Hewan {
    protected String nama;

    Hewan(String nama) {
        this.nama = nama;
    }

    void makan() {
        System.out.println(nama + " sedang makan");
    }
}

class Kucing extends Hewan {
    Kucing(String nama) {
        super(nama);
    }

    void mengeong() {
        System.out.println(nama + ": Meong!");
    }
}

Kucing IS-A Hewan, jadi object kucing dapat memakai method warisan seperti makan() sekaligus memiliki perilaku khusus mengeong(). Constructor subclass memanggil super(nama) sebagai langkah pertama agar bagian superclass terinisialisasi sebelum bagian subclass.

Inheritance cocok untuk relasi “adalah jenis dari”. Kalau relasinya “memiliki”, biasanya gunakan composition dengan menyimpan object lain sebagai atribut.
06

Class diagram: inheritance dan composition

Pertemuan ini menggabungkan relasi class dengan studi kasus kendaraan dan tiket parkir. Di class diagram, nama class, atribut, method, dan relasi menunjukkan struktur program.

  • IS-A: Mobil dan Motor adalah Kendaraan — gunakan inheritance (extends).
  • HAS-A: TiketParkir memiliki object Kendaraan sebagai atribut — ini composition, bukan inheritance.
  • Dependency: Main menggunakan class lain untuk menjalankan program.
  • Constructor overloading memberi pilihan membuat tiket dengan atau tanpa tarif per jam; static jumlahTiket menghitung tiket bersama.
class Kendaraan {
    private String nomorPolisi;
    private String merk;

    Kendaraan(String nomorPolisi, String merk) {
        this.nomorPolisi = nomorPolisi;
        this.merk = merk;
    }

    public String getNomorPolisi() { return nomorPolisi; }
    public String getMerk() { return merk; }
}

class Mobil extends Kendaraan {
    private int jumlahPintu;

    Mobil(String nomorPolisi, String merk, int jumlahPintu) {
        super(nomorPolisi, merk);
        this.jumlahPintu = jumlahPintu;
    }
}

class Motor extends Kendaraan {
    private String jenisMotor;

    Motor(String nomorPolisi, String merk, String jenisMotor) {
        super(nomorPolisi, merk);
        this.jenisMotor = jenisMotor;
    }
}
class TiketParkir {
    private static int jumlahTiket = 0;
    private Kendaraan kendaraan; // HAS-A
    private double tarifPerJam;

    TiketParkir(Kendaraan kendaraan) {
        this(kendaraan, 5000);
    }

    TiketParkir(Kendaraan kendaraan, double tarifPerJam) {
        this.kendaraan = kendaraan;
        this.tarifPerJam = tarifPerJam;
        jumlahTiket++;
    }

    static int getJumlahTiket() {
        return jumlahTiket;
    }
}
Ingat untuk diagram: panah inheritance mengarah dari subclass ke superclass; atribut object pada TiketParkir menggambarkan HAS-A. Hubungan penggunaan oleh Main adalah dependency, bukan IS-A.

Class diagram membantu merancang struktur sebelum kode ditulis: kotak class merangkum atribut dan method, sementara garis dan panah menyatakan hubungan. Composition menaruh object bagian sebagai atribut class pemilik; tiket parkir mencatat kendaraan yang sedang diparkir, tetapi bukan jenis kendaraan.

07

Polymorphism, casting, dan dispatch

Polymorphism berarti satu pemanggilan dapat menghasilkan perilaku berbeda. Overloading memakai nama method sama dengan parameter berbeda dan dipilih compiler. Overriding mengganti implementasi method warisan; saat runtime JVM memilih implementasi berdasarkan tipe object sebenarnya.

class Bentuk {
    double luas() { return 0; }
}

class Lingkaran extends Bentuk {
    private double jariJari;

    Lingkaran(double jariJari) {
        this.jariJari = jariJari;
    }

    @Override
    double luas() {
        return Math.PI * jariJari * jariJari;
    }
}

Bentuk bentuk = new Lingkaran(3); // upcasting otomatis
System.out.println(bentuk.luas()); // method Lingkaran dipanggil
  • Upcasting: referensi subclass ke tipe superclass; otomatis dan aman.
  • Downcasting: referensi superclass ke subclass; eksplisit dan hanya aman bila object memang tipe tersebut. Periksa dengan instanceof.
  • Dynamic method dispatch: pemilihan method override berdasarkan tipe object aktual, bukan tipe referensi.
if (bentuk instanceof Lingkaran) {
    Lingkaran lingkaran = (Lingkaran) bentuk;
    System.out.println(lingkaran.luas());
}

Overloading dan overriding berbeda: overloading mengubah daftar parameter, sedangkan overriding mempertahankan signature method superclass dan mengganti perilakunya.

Manfaatnya: kode pemanggil dapat bekerja dengan tipe induk yang sama, sementara tiap object memberi perilaku yang sesuai dengan jenis konkretnya.

Studi kasus dari praktikum

Contoh berikut merangkai beberapa konsep PBO dalam alur yang lebih nyata. Tiap kasus menyorot masalah, desain object, dan konsep yang muncul.

1. Transaksi e-commerce: saldo dan stok

Di contoh MainPengguna.java, object pengguna membeli object produk. Method transaksi menghitung total, membandingkan dengan saldo, lalu hanya mengubah saldo dan stok jika saldo cukup. Kondisi gagal tidak boleh mengurangi stok.

class Produk {
    String nama;
    double harga;
    int stok;

    Produk(String nama, double harga, int stok) {
        this.nama = nama;
        this.harga = harga;
        this.stok = stok;
    }
}

class Pengguna {
    String nama;
    double saldo;

    Pengguna(String nama, double saldo) {
        this.nama = nama;
        this.saldo = saldo;
    }

    void beli(Produk produk, int jumlah) {
        double total = produk.harga * jumlah;
        if (jumlah > 0 && jumlah <= produk.stok && saldo >= total) {
            saldo -= total;
            produk.stok -= jumlah;
            System.out.println("Transaksi berhasil");
        } else {
            System.out.println("Transaksi gagal");
        }
    }
}

Konsep: object saling berinteraksi lewat method dan parameter. Perhatikan validasi stok, jumlah, dan saldo sebelum mengubah state object.

2. Tiket parkir: relasi kendaraan

Kasus laporan pertemuan 6 memodelkan kendaraan umum, variasi mobil/motor, dan tiket yang merekam kendaraan. Mobil dan motor adalah kendaraan (IS-A); tiket memiliki kendaraan (HAS-A). Counter static mencatat jumlah tiket lintas object.

class Kendaraan {
    private String nomorPolisi;
    private String merk;

    Kendaraan(String nomorPolisi, String merk) {
        this.nomorPolisi = nomorPolisi;
        this.merk = merk;
    }

    String getNomorPolisi() { return nomorPolisi; }
    String getMerk() { return merk; }
}

class Mobil extends Kendaraan {
    private int jumlahPintu;

    Mobil(String nomorPolisi, String merk, int jumlahPintu) {
        super(nomorPolisi, merk);
        this.jumlahPintu = jumlahPintu;
    }
}

class TiketParkir {
    private static int jumlahTiket;
    private Kendaraan kendaraan;
    private double tarifPerJam;

    TiketParkir(Kendaraan kendaraan) {
        this(kendaraan, 5000);
    }

    TiketParkir(Kendaraan kendaraan, double tarifPerJam) {
        this.kendaraan = kendaraan;
        this.tarifPerJam = tarifPerJam;
        jumlahTiket++;
    }
}

Konsep: super(...) mengisi data bagian superclass; overloaded constructor menyediakan tarif default atau tarif khusus; composition memisahkan tanggung jawab tiket dari detail kendaraan.

3. Penggajian: polymorphism pegawai

Contoh TugasMandiriPegawai.java menyimpan berbagai jenis pegawai dalam array bertipe induk. Saat hitungGaji() dipanggil, Java menjalankan implementasi sesuai object sebenarnya. Pegawai tetap menambahkan bonus; method bonus juga di-overload agar bisa memakai persentase eksplisit.

class Pegawai {
    String nama;
    double gajiPokok;

    Pegawai(String nama, double gajiPokok) {
        this.nama = nama;
        this.gajiPokok = gajiPokok;
    }

    double hitungBonus() { return 0; }
    double hitungBonus(double persen) { return gajiPokok * persen; }
    double hitungGaji() { return gajiPokok + hitungBonus(); }
}

class PegawaiTetap extends Pegawai {
    double persenBonus;

    PegawaiTetap(String nama, double gajiPokok, double persenBonus) {
        super(nama, gajiPokok);
        this.persenBonus = persenBonus;
    }

    @Override
    double hitungGaji() {
        return gajiPokok + hitungBonus(persenBonus);
    }
}

Pegawai[] pegawai = {
    new Pegawai("Andi", 5_000_000),
    new PegawaiTetap("Budi", 6_000_000, 0.10)
};

for (Pegawai p : pegawai) {
    System.out.println(p.nama + ": " + p.hitungGaji());
}

Konsep: upcasting terjadi saat PegawaiTetap dimasukkan ke array Pegawai[]. Dynamic dispatch memilih hitungGaji() yang override saat runtime; overloading membedakan hitungBonus() dan hitungBonus(double) dari parameternya.
